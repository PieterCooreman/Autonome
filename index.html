Architecture & file layout

A handful of files. Self-hosted on ASPPY (Classic ASP/VBScript runtime for Python). No npm, no build step.

Project folder structure
autonome/
├── app.db              # SQLite database
├── index.html          # React SPA UI
├── script.js           # React logic
├── style.css           # UI styling
├── api.asp             # REST JSON API
├── favicon.ico
├── robots.txt
└── sites/
    └── <random-16-char>/   # One folder per project
        ├── index.html      # Generated site
        ├── img/            # Uploaded photos
        └── backups/
            └── <timestamp>/  # Version history
How it connects
  • React SPA - The browser loads index.html + script.js. All navigation is client-side via URL fragments (#/...).
  • ASPPY Runtime - Serves static files and routes API calls to api.asp (Classic ASP on Python).
  • SQLite (app.db) - Stores users, projects, config, jobs, chat history. Created automatically on first request.
  • LLM Endpoint - Your local LM Studio / Ollama server or Anthropic API. The agent sends prompts and receives complete HTML.

The API at a glance

The SPA talks to api.asp over JSON. All actions are session-authenticated with cookie-based sessions.

Action Purpose
setup, login, logout, session, registerAuthentication & account management
change_password, update_email, forgot_password, reset_passwordPassword & email management
get_config, save_config, list_modelsAdmin LLM & email configuration
get_projects, create_project, rename_project, copy_project, delete_project, reset_project, update_notesProject management
generate_website, generate_worker, generate_status, cancel_generation, active_job, keepaliveAI generation jobs (async)
upload_image, list_images, delete_imageImage handling & auto-resize
list_backups, restore_backup, preview_backup, download_project, get_project_filesVersion history & exports
get_chat_historyPer-project chat log
admin_get_users, admin_update_userUser administration
version, pingHealth & version info
Sessions: Cookie-based. The SPA pings keepalive every 5 minutes while logged in. Project operations verify ownership (user_id), backups and filenames are checked against path traversal, and project folders use random names so usernames never appear in URLs.

Tips for best results

  • 1
    Be specific. Mention goal, audience, colors, style, tone and the content you want.
  • 2
    Upload photos first. The agent can design around them for much better results.
  • 3
    Iterate. Don't expect perfection in one shot - ask for refinements in plain language.
  • 4
    Use suggestions. Discover useful improvement patterns with the built-in prompt library.
  • 5
    Write in your own language. The generated site is written in the same language as your request.
  • 6
    Raise max_tokens if you see "cut off by the token limit" errors.

Security notes

  • Change default credentials immediately after first login (admin / admin123).
  • Bcrypt hashes for passwords. Reset tokens are single-use and expire after 1 hour.
  • Session-authenticated API. Project operations verify ownership (user_id).
  • Path traversal protection on backups and filenames. Random project folder names.
  • Limited outbound requests - only to your configured LLM endpoint and optionally Wikipedia.
  • ValidateFileExtension refuses any filename other than index.html. Structural completeness check before saving - a broken AI response never overwrites your site.

Privacy Cookies / Cookie settings
Cookies

Autonome uses the following cookies:

  • session (functional) - Maintains your login session via HTTP cookie. Expires when you close the browser or log out.
  • cookieConsent (localStorage) - Stores whether you accepted or rejected cookies. No tracking or marketing cookies are used on this site.

If embedded content (maps, video, analytics) is added later, it may set its own cookies - see the Privacy statement for details.

Privacy statement

Data controller: Autonome (self-hosted).

What we collect:

  • User-provided data: username, email address, password (bcrypt hash), project names and notes.
  • Generated websites: index.html files stored in per-project folders.
  • Uploaded images: stored in each project's img/ folder (auto-resized to max 1920 px).
  • Chat history: prompts and AI responses per project, stored in SQLite.
  • Server logs: IP address and user agent for security purposes.

Purpose & legal basis:

  • To operate and secure the website (legitimate interest / contract).
  • To respond to your requests via the AI agent (consent).
  • To send password-reset and generation-finished emails (optional, consent-based).

Data sharing: No data is sold. Outbound requests go only to your configured LLM endpoint and optionally to the public Wikipedia API.

Retention: Server logs are kept briefly. Form/chat data is retained as long as the project exists. Reset tokens expire after 1 hour and are single-use.

Your rights: You may request access, correction or deletion of your data. Admins can manage users and promote/demote roles.
